<objective>
Turn the already-immutable, never-overwritten checkpoint history (train.py writes `models/run-{iteration:02d}-{timestamp}.pt`, D-10) into user-facing model version-history + rollback. Add an app-layer append-only run registry (`models/runs.jsonl`), an `models/ACTIVE` pin pointer with an `_active_checkpoint()` resolver, a `/models` view that lists run history with an "active" badge and a "Use this one" activate control, and a `POST /models/activate` route guarded by registry membership. Swap `/generate`'s checkpoint resolution from `_latest_checkpoint()` (Plan 05-04) to `_active_checkpoint()`.

Purpose: Let the user audition past models and roll back generation to any prior checkpoint, with a pin that persists across later retrains — provenance + rollback for the local demo (SC#8).
Output: `apollo/app/registry.py`; `_active_checkpoint()` + `/models` + `/models/activate` in `app.py`; a completion hook in `jobs.py` that records each finished run; `models.html`; a dashboard link; registry + models-route tests.

Known limitation (NOTE, do not solve): the registry is written by the **app layer** (TrainingJob completion handler), NOT by `train.py`. CLI-only training (`python -m apollo.scripts.train ...` run outside the app) will produce a checkpoint but will NOT populate `runs.jsonl` in v1. `_active_checkpoint()`'s mtime fallback still surfaces such checkpoints to /generate; they simply won't appear in the /models history until a future enhancement teaches the CLI to log runs.

Reproducibility caveat (NOTE, do not build): model rollback ≠ full reproducibility. Every train is full-from-scratch on the whole corpus (D-05), so lineage is corpus→model, not checkpoint→checkpoint. The `corpus_hash` in APP-14 only *flags* "this checkpoint was trained on a different corpus than you have on disk now"; it does not snapshot the corpus. Full corpus snapshotting is deferred to **SEED-011** — reference it in code comments, do not implement here.
</objective>

def _launch_training():
    models_dir = "models"
    corpus_hash = registry.compute_corpus_hash(app.config["PAIRS_ROOT"])
    pair_count = len(_known_pairs_set())
    def _on_complete(train_loss, held_loss):
        ckpt = _latest_checkpoint()          # newest .pt by mtime == the run just produced
        if ckpt is None:
            return
        registry.append_run(
            models_dir,
            checkpoint=ckpt.name,
            iteration=1,                      # train.py default iteration (CLI flag not set by app)
            corpus_pair_count=pair_count,
            corpus_hash=corpus_hash,
            held_loss=held_loss,
            train_loss=train_loss,
        )
        # NOTE: pin-vs-retrain (D-06) — appending a run does NOT touch ACTIVE.
        # A new run only becomes active if the user is on latest (ACTIVE unset)
        # or explicitly activates it (Task 3). We never auto-move an existing pin.
    return app.config["TRAINING_JOB"].start(str(app.config["PAIRS_ROOT"]), 300, models_dir, on_complete=_on_complete)
```

def _active_checkpoint():
    """Resolve the checkpoint /generate should use.

    Pin-vs-auto-retrain rule (D-06): if models/ACTIVE names a checkpoint that
    still exists on disk, return THAT (the user pinned a specific model and
    later retrains must not steal the pin). Otherwise fall back to newest-by-mtime
    (== "latest", the default when ACTIVE is unset OR the pinned file was deleted).
    """
    name = registry.get_active("models")
    if name:
        candidate = Path("models") / name
        if candidate.is_file():
            return candidate
        # stale pin (file deleted) → fall through to latest
    return _latest_checkpoint()
```
