Wire the corpus-building and training backend AND the browser-side upload UI that drives it: a server-side drag-drop ingest that reuses the shipped validators and renders the canonical call.wav in-process, the corpus-view upload form that POSTs a pair to /ingest, a manual + debounced-auto Train flow that subprocesses the shipped train.py, the live training view (progress bar + loss curve via polling), and a configurable response-storage setting.

Purpose: Close the "build corpus → train locally → watch it learn" loop end-to-end — from a browser file picker through the shipped validators to a rendered pair on disk — using only shipped, tested code (D-02/D-05/D-11/D-13), keeping one validation source of truth so app errors match the CLI exactly.
Output: `/ingest`, `/train`, `/settings` routes; upload UI in `corpus.html`; `training.html`; polling + ingest (multipart FormData) handlers in `app.js`.
