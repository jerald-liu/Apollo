<objective>
Close the train/serve gap and reconcile the docs/requirements that still assume Ableton.

`generate.py` currently requires a `call.wav` file argument. Replace that with on-the-fly rendering from `data/pairs/NNN/call_fm.json` using the SAME `render_call_wav` the corpus uses (RESEARCH Option A) — this is what guarantees inference and training share one renderer with no domain gap. Critically, generate.py already computes `call_bpm` via `estimate_tempo()` and parses `call_notes` via `load_notes`; the render must reuse that SAME parse (pass `call_bpm`/`notes` through) so the MIDI is never parsed twice under different tempo assumptions.

Then update `CORPUS-CONVENTIONS.md` (de-Ableton the authoring workflow; `call.wav` becomes derived) and `REQUIREMENTS.md` (DATA-01/02 superseded by DATA-06), and gitignore rendered wavs.

Purpose: DATA-06's "same engine renders inference-time calls" requirement; remove the Ableton-bounce premise that this phase obsoletes. This phase BLOCKS DATA-05 — after it lands, corpus authoring can resume against the FM-manifest workflow.
Output: edited `generate.py`, `CORPUS-CONVENTIONS.md`, `REQUIREMENTS.md`, `.gitignore`.
</objective>
