   - v4 should be past step ~500-1000 by 30 minutes (faster, larger batch + compile)

<task type="checkpoint:human-verify" gate="blocking">
  <name>Task 2: Mid-run health check at ~20K steps (~3-4 hours in)</name>
  <read_first>
    - Terminal output / Modal dashboard for both runs at ~20K steps
  </read_first>
  <what-built>Both runs have been training for several hours since Task 1 confirmation.</what-built>
  <how-to-verify>
Check both runs approximately 3-4 hours after launch (when v3 should be ~15K-20K steps and v4 ~20K-25K steps).

For each run:

1. Verify step counter is still advancing (not stalled):
   - Look for recent log lines with step numbers in the 15K-25K range

2. Check val loss is still decreasing:
   - v3 at 20K: should be ~2.3-2.5 (well below 3.0, declining trend)
   - v4 at 20K: should be ~2.3-2.5 (declining trend)

3. Confirm no loss explosion (loss should not have spiked above 5.0 after step 5K):
   - Scan log for any `loss` values > 5.0 after the warmup phase (first 1000 steps)
   - A spike and recovery is acceptable; a spike and plateau is a divergence signal

4. Check tok/s is still healthy (not dropped to near-zero which indicates a stall):
   - v3: >5,000 tok/s sustained
   - v4: >15,000 tok/s sustained

INTERVENTION — if loss exploded (>5.0 after step 5K, not recovering):
  Kill the diverged run. Resume from latest checkpoint:
  ```
  make modal-train CONFIG=configs/vN_XXX.yaml RESUME=checkpoint_latest.pt
  ```
  Note: RESUME path is relative to the run's checkpoint subdir — modal_train.py handles the full path.

INTERVENTION — if run terminated (Modal timeout or preemption):
  Resume: `make modal-train CONFIG=configs/vN_XXX.yaml RESUME=checkpoint_latest.pt`
  Modal timeout is 12h (see modal_train.py timeout=60*60*12) — if both runs take ~10-12h they should complete.
  </how-to-verify>
  <resume-signal>Paste val loss readings for each run at ~20K steps (e.g., "v3: VAL step 20000 | loss 2.3812  v4: VAL step 20500 | loss 2.4102"), or describe intervention taken if needed</resume-signal>
  <acceptance_criteria>
    - v3 val loss at step ~20K is less than 2.7 (meaningful improvement from starting ~3.0)
    - v4 val loss at step ~20K is less than 2.7 (meaningful improvement from starting ~3.0)
    - Both step counters have advanced at least 15,000 steps from the previous check
    - No irreversible training failures (if intervention was needed, the run has been successfully relaunched)
  </acceptance_criteria>
  <done>Both runs confirmed healthy at the 20K-step mark with descending val loss; any recovery actions complete</done>
</task>
